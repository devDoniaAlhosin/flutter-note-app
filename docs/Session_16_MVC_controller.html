1What MVC is

MVC means Model, View, Controller. Each part has one job so the screens do not talk to the database.

Model

The data. Note has id, title, description, and times. It does not draw UI.

View

The screens. Home shows the list and search. The editor shows Title and Description. The view only calls the controller.

Controller

NotesController loads, saves, deletes, and searches. It talks to the repository and DatabaseHelper.

1. View action 2. NotesController 3. Repository / SQLite 4. View updates

2What I edited in Session 16

  1. I added lib/controllers/notes_controller.dart. This is the controller. Views call it. It does not build widgets.
  2. I moved the note logic out of NotesProvider into NotesController: load, save, delete, restore, search.
  3. I updated the views so home and editor use context.read / watch<NotesController>.
  4. I updated main.dart to provide NotesController instead of NotesProvider.

Session 13 screens, Session 14 emit/omit, and Session 15 DatabaseHelper stay. Session 16 only changes who the view talks to.

3What the controller does

After a change the controller emits with notifyListeners(). The home view watches it, so the list rebuilds.

Controller method What it does
loadNotes() Reads notes from SQLite and emits the list.
saveNote() Create inserts one row. Edit updates that row. Then emit.
deleteNote() Removes one row and emits.
restoreNote() Undo after swipe. Inserts the note again.
setSearchQuery() Emits a new query. Unmatched notes are omitted from visibleNotes. 
View  →  NotesController.saveNote(note)
     →  NoteRepository.insertNote / updateNote
     →  DatabaseHelper (one SQLite row)
     →  notifyListeners()
     →  Home view rebuilds
