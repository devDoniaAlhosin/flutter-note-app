1Edits in each session

I used the same Notes app for Week 7. Each session added one piece.

Session 13 — Notes app

I built the home list and the editor. Each note has a title and a description. I can add, edit, search, swipe-delete, and save with the check button. Back asks “Are you sure?”

Session 14 — Provider, emit, omit

I moved notes into NotesProvider. After a change I emit with notifyListeners(). I omit empty notes, unmatched search, and unsaved back.

Session 15 — DatabaseHelper

I replaced SharedPreferences JSON with SQLite. Create, edit, and delete now change one row through DatabaseHelper. SQL stays in one class so screens do not write SQL.

Session 16 — MVC controller

I split the app into Model (Note), View (screens), and Controller (NotesController). Screens call the controller. The controller talks to the database.

2What I did

  1. I turned the Flutter starter into a Notes app named Notes, with a title and description on every note.
  2. I built the home list and the editor screens so I can add, open, and change notes.
  3. I used MVC with a controller (NotesController). The view calls the controller. The controller updates the model and SQLite.
  4. I applied emit and omit on the note screens. Save, delete, and search emit a new state. Empty notes, unmatched search, and back without the check are omitted.
  5. I saved notes in SQLite with DatabaseHelper. Create inserts one row. Edit updates that row. Delete removes that row.
  6. I added search, swipe delete with undo, and a check button to save. Going back asks “Are you sure?”

4Provider, emit, and omit

Session 16 uses MVC. The view calls NotesController. The controller emits with notifyListeners(). Omit means I skip what should not be saved or shown.

1. Note screen action 2. NotesController 3. Emit or omit 4. Home list updates
Emit

After save, delete, undo, or a new search, Provider calls notifyListeners(). The home screen uses watch, so the list rebuilds with the new notes.

Omit

I omit an empty note (no title and no description). I omit notes that do not match search. I omit a refresh if the search text did not change. I omit save if I go back without the check.

On the note screen What happens
Press the check Emit the new or updated note to the list.
Swipe delete or undo Emit the list without that note, or put it back.
Type in search Emit the query. Omit notes that do not match.
Empty title and description Omit the save. Show a snackbar instead.
Back without the check Omit the draft. Ask “Are you sure?”

I do not call emit() in the widget. The editor calls saveNote or deleteNote. Provider emits. The home screen updates.

5File structure

MVC: View talks to Controller. Controller talks to the repository. The repository talks to DatabaseHelper.

File What it does
lib/main.dart Starts the app, sets the theme, and wraps the app with ChangeNotifierProvider. No SharedPreferences init.
lib/models/note.dart The Note model: id, title, description/content, created time, updated time, and JSON helpers.
lib/data/database_helper.dart Session 15 SQLite helper. Opens notes.db, creates the notes table, and runs insert, update, delete, and get for one note at a time.
lib/data/note_repository.dart Asks DatabaseHelper to load, insert, update, or delete a note. Screens do not write SQL.
lib/controllers/notes_controller.dart Session 16 MVC controller. Add, update, delete, restore, and search. Views call it. It emits with notifyListeners() and talks to the repository.
lib/screens/notes_home_page.dart View: watches the controller, shows notes, omits notes that do not match search.
lib/screens/note_editor_page.dart View: check asks the controller to save. Empty note is omitted. Back omits unsaved text and asks “Are you sure?”
android/.../strings.xml Sets the Android app name to Notes.
docs/Note_app_Documentation.html This Notes App Documentation page. It covers sessions 13, 14, 15, and 16 in one file.
